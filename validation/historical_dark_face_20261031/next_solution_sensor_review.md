# 下一步曝光／增益方案只读核查

本次只读当前源码和已有官方手册审计，没有硬件访问、生产RTL改动、编译或Git提交。当前用户未确认历史镜像的OSD档位，因此不能认定本次已实测曝光900仍饱和。

## 结论

900不是传感器下限，只是当前四档菜单的最低预设；可以增加600/450/300等短曝光。但当前增益请求仍为标称24倍，按现有官方手册控制建议，**优先验证并降低增益，再判断是否需要低于900**。仅继续缩短快门、然后大幅数字提亮，会进一步损失暗部光子信号，放大原有色噪和肤色问题。

最小可靠实验是固定同一真实曝光请求，关闭C/P/W，维持认可的AWB、Gamma、shading、Logo，仅切换gain索引160/144/112/80，对应标称24/16/8/4倍。必须分清“数字增益降低”和“模拟增益降低”：前者可以释放输出码值余量，不能保证恢复已在模拟／ADC环节丢失的高光。

## 建议阶段

1. 先由用户确认当前历史镜像“原图3”，固定场景；不据下载成功推断900已经应用。保存同一镜像原图0/3观察，辨别用户记忆与目前照明差异。
2. 第一个新候选只改前端gain：固定一个已确认的曝光、160/144/112/80四档，保留其它图像链。在既有AE表完成后，利用同一I2C控制器做少量一次性寄存器读回并留PC记录；不堆常驻大诊断模块。不需要另加DSP/ERAM或帧缓存，少量控制状态、寄存器和OSD的实际Slice仍需编译报告核对。
3. 若最低合理gain下仍有传感器饱和，再测试900/600/450/300曝光，gain保持不变。若正常室内场景，另核1200=10ms与低gain组合；不要一次混改快门、gain、AWB和局部补偿。
4. 找到能保亮部的前端工作点后，复用现有H1/C乘法路径做有上限的非高光提亮，不增加DSP。亮度保留必须有实测对比；不强行补回任意倍曝光差，不把饱和白块压灰称为找回细节。现有强C3已暴露噪声与层次代价，应选最低必要补偿。
5. 手动候选可靠后再做低速闭环：高光过量时先减gain、gain已低再减曝光；过暗时先加曝光至防闪烁／运动上限，再加模拟gain，最后数字gain。以高光分位或过亮像素比例作为限制，不能用整帧均值单独决定；使用迟滞、最小保持时间、有限步长和I2C完成握手。MCU适合这类低速决策，但当前A版为被动接入，尚无该控制桥，不能假装已经MCU闭环。应维持单I2C所有权，通过小型请求／完成接口，禁止两个主机同时驱动。

## 颜色、资源及能力边界

- AWB会受曝光改变而改变统计样本：`awb.v:203`排除RGB和≥720及肤色样本，增益限0.5～2倍，约1/64帧间平滑。每档需等待稳定再比较；短曝光和gain变化引起的肤色变化不能直接归因于新色彩算法。
- 当前color_shading对R/B作空间增益，G直通；会在通道高光处先裁剪。前端降低信号有机会减少这类裁剪，并保留用户认可的空间校正；无需再关shading。后置P/W只能对尚存数值映射，不能逆转RAW／AWB／shading已丢失细节。
- 当前Gamma尾段已修连续，不应再次以Gamma作为前端已饱和的解决方案。
- 高光驱动AE的统计需选择源位置；最好在AWB/Gamma裁剪前统计，至少区分单通道削顶与整体亮度。但这是后续闭环设计，不能未经资源核算加整幅直方图、额外乘法或帧缓存。
- 单曝光暗部信号的SNR由采集条件限制；低曝光再强提亮不会凭空增加暗部信息。任意大动态范围同时兼顾需要改变照明／传感器HDR或多曝光融合，后者有运动、缓存与资源成本。本轮优先前端工作点＋现有有限补偿。
